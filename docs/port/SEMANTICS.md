# Python 3.11 → Dart 3.13 语义差异

本表使用 Android 1.7.5 的 Python 3.11 作为标准答案。A0 的语义测试可位于 `core/test/semantics/`，不表示对应业务函数已移植；业务完成状态只看 `MANIFEST.yaml`。生成器输出的 JSONL 是两边读取的同一组输入与 Python 预期输出。每一行都写明尚需完成的逐位点验证，避免把小样本通过误当成全模块通过。

| 主题 | Python / Dart 差异 | 统一规则和两边可运行的测试 | 尚需核对 |
|---|---|---|---|
| 字符串下标与正文位置 | Python `len`、切片和正则 span 按 Unicode 码点；Dart 字符串下标按 UTF-16 码元。`𠮷`、emoji 都占前者 1、后者 2。 | 磁盘和阅读器可见的 `start/end/frontier` 统一用 UTF-16；局部 Python 算法用码点时显式转换。`oracle/semantics/general.jsonl` 中 `code_point_length`、`utf16_length`、`utf16_offset`、`utf16_prefix`、`slice` 共用 `A𠮷😀B` 等样本；`utf16_offsets.json` 还冻结 `Runner._text_around` 的混合单位行为。Python `tests/test_port_semantics.py`、`tests/test_utf16_offsets.py` 与 Dart 对应语义测试运行。27 个疑似函数及 14 个显式编码位点的分类见 `UTF16-AUDIT.md`。 | 业务函数移植时须分别核对码点、UTF-16、字节长度，尤其不能自行改变 `_text_around` 已冻结的结果。 |
| 正则 | Python `re` 的 Unicode `\w/\b/\d/\s`、命名组 `(?P<...>)`、绝对结尾 `\Z`、`S/M/X`、`fullmatch`、带组 `split`、`sub` 替换格式与 Dart `RegExp` 有差异；Python span 仍是码点。 | `docs/port/REGEX.json` 按 AST 记录 112 个直接调用（`pipeline.parse` 为 34 个）及 36 个编译模式调用；141 个静态位点、12 个可枚举动态变体均有正反例。`oracle/semantics/regex_python.py` 与 `core/test/semantics/regex_test.dart` 对同一用例执行。另有 `regex_operations.jsonl` 的 26 个操作级用例，Python `tests/test_regex_operations.py` 与 Dart `regex_operations_test.dart` 测捕获、Unicode 类、S/M/X、完整匹配、带组拆分、替换与位置。`surface_regex.jsonl` 通过实际 `KG.plan` 录制 6 组表面名动态模式：CJK、拉丁边界、重叠、标点、空模式和过滤为空；Python `tests/test_surface_regex.py` 与 Dart `surface_regex_test.dart` 对比匹配文本、组及码点/UTF-16 位置。5 个 AST 动态位点中，其余 3 个具有可枚举变体，见 `REGEX.md`。 | 用例只证明所列输入；测试适配器不是通用翻译器。字节/ASCII/locale 标志、复杂 X 模式、八进制替换及模型生成的 surface 全范围仍须随 A4 的逐函数 golden 核对。 |
| JSON 序列化 | Python `json.dumps` 默认空格、ASCII 转义、键排序和浮点表示影响哈希/缓存键；Dart 默认编码不保证逐字节相同。Python 允许 `NaN/Infinity` 和任意长度整数。 | `PyJson` 明确 `ensureAscii/sortKeys/compact/allowNan`，保留插入顺序并拒绝无序集合；大整数用 `BigInt` 写出完整十进制文本。`oracle/semantics/py_json.jsonl` 固定随机种子录制 10,000 个值；`numeric_boundaries.jsonl` 补充超 64 位整数和布尔键排序。两边测试逐字节比较，另测非有限值、Unicode 键序。 | 业务函数的具体 `json.dumps` 选项要随 golden 核对；Dart `Map` 对 `true` 与 `1` 的键等价规则不同，暂不能拿这种混合键映射充当 Python `dict`。 |
| 哈希和来源校验 | UTF-8 字节、JSON 字节、文件内容只差一个字符，SHA-256 与旧缓存键就失效；`EXTRACTOR_REVISION` 哈希了原 `pipeline/local.py` 源码。 | 固定 Python 1.7.5 `local.py` 的修订哈希 `2ead2ec689628def6e1b12c657e554008571d3717a2b42ab6fbce98184fc0f55`；`oracle/semantics/hashes.jsonl` 的 12 例在 Python 和 Dart 逐字节比 SHA-256。 | 清单中的所有哈希调用点仍需在各自函数 golden 覆盖，特别是 1.7.x 已付费缓存。 |
| 字符串方法 | Python 默认 `strip/split` 使用 Unicode 14 空白集合；`isdigit` 含非 ASCII 数字；`casefold/title` 与 Dart 小写/大写转换不同。Greek final sigma 要越过大小写可忽略字符寻找前后文，其中 U+0345 同时是 cased 和 case-ignorable。 | 以 Python 3.11 Unicode 14 表生成 `unicode_data.dart`；`general.jsonl` 的常规样本及 `title_context.jsonl` 的 378 个组合由两边测试。包含全角空格、NBSP、Greek sigma、组合音标、撇号、ZWJ、`ß`、阿拉伯数字、上标数字。 | 逐业务函数核对调用参数、空串和 Unicode 异常输入。 |
| 数字 | Python `//` 向负无穷取整，`%` 的符号随除数，`int(float)` 向零截断；`round` 在正好一半时取偶数，`round(x, n)` 基于二进制浮点值。Python 整数不受 Dart VM 的 64 位宽度限制；`num.compareTo` 对带符号零和 NaN 的排序也不同。 | `general.jsonl` 的常规样本、`round_extremes.jsonl` 的 700 个浮点舍入极值及 `numeric_boundaries.jsonl` 的 74 个整数宽度、NaN、带符号零、混合比较边界由两边测试。兼容层以 IEEE-754 的精确分数计算无位数 `round`/`int(float)`，必要时返回 `BigInt`；除法和取模接受 `int`、`BigInt` 或 Python 整数语义下的 `bool`，在溢出边界保持 Python 结果。Python `OverflowError` 映射为 Dart `RangeError`，`ValueError` 映射为 `ArgumentError`。 | 业务调用仍须随函数 golden 核对输入范围；在需要原生 `int` 的位置显式证明结果未超过 64 位。 |
| 排序 | Python `sorted` 稳定、比较 key 元组时逐元素按码点/数字比较；Dart 的默认排序和字符串顺序不可直接代用。 | Dart 显式附原索引保证相等 key 的顺序；`general.jsonl` 的 `compare/stable_sort` 加 `numeric_boundaries.jsonl` 的带符号零、NaN、64 位边界混合比较在两边运行。 | 各业务 `key=`、`reverse=` 与不支持的混合类型须随函数 golden 核对；Python 对 NaN 不给出全序，不能把该比较器当全序使用。 |
| 字典顺序 | Python 3.11 `dict` 保留首次插入位置，覆盖已有 key 不改变位置；Dart `HashMap` 不保证顺序。 | 使用 `LinkedHashMap`；`general.jsonl` 的 `ordered_map` 在两边运行，`PyJson` 对无序 `HashMap` 明确拒绝。 | 各持久化字典的插入顺序仍需整书及接口 golden 证明。 |
| 时间与随机 | Python `time.time/monotonic` 与 `random.random` 直接读取全局状态会使重试及输出不稳定。 | 核心接口接受 `ClockSource/RandomSource`；`oracle/semantics/determinism.jsonl` 由固定时钟和抖动录制四种 `Retry-After`，Python 和 Dart 测试读取同样的预期。 | A3 业务模型客户端要真正使用注入接口；录制中的导出时间、Cookie 需在复跑中验证稳定。 |
| 并发完成顺序 | Python `ThreadPoolExecutor` 工作完成时序不固定；`ex.map` 和逐索引取 `Future.result` 仍按输入顺序发出。Dart `Future.wait` 也按输入列表发出。 | Python `test_executor_map_publishes_in_input_order` 用事件迫使第二项先完成；Dart `determinism_test.dart` 用两个 `Completer` 反序完成，同测输出 `[0,1]`。A0.5 已在 Python 给同位点 finalization 稳定排序，并在跨章读取新上下文前等待当前章后台任务；受控测试验证两种流程和续跑。阿Q 9/9 段与 Jekyll 19/20 段的同配置离线回放均已两遍逐字节一致；函数级录制还以两种 `PYTHONHASHSEED`、相同阿Q录音带双遍逐字节一致。 | Jekyll 20/20 和其余三本公开书仍缺完整真实录音带；Jekyll 的并发度 12 会生成现有录音带没有的前瞻请求，不能把并发度 1 的结果当作默认并发度验收。A5 的 Dart 调度仍须逐字段对照。 |

## 用例运行方式

从仓库根目录运行 Python 3.11 的 `python -m unittest tests.test_port_semantics oracle.semantics.regex_python`；从 `core/` 运行 `dart test test/semantics`。`dart analyze --fatal-infos --fatal-warnings` 负责类型与 lint。正式验收以 CI 和 `STATUS.md` 记录的运行结果为准。
