# 长篇翻页优化（2026-10-15）

主分支整合了远程 PR #5、#6、#7、#8、#16、#17。重构的网页版拆分采用同一 Dart library 的 part 文件，保留原有私有类型、导入路径，以及阅读体验新增功能。恢复了 queueFinal 的整理范围判断，以及人物小传暂缓时提前返回的判断，避免暂缓任务被错误写成 complete。

## 性能

ReaderController 原来在每次 pageAt 调用时，从打开书时的章节开始遍历。连续跨章阅读时，定位工作随距离增加。onPage 现在将定位起点移至实际显示的页。虚拟页码、generation、原文位置和阅读截止保持原有含义。

同一台 Mini（M4 / macOS 15.7.5 / Flutter 3.47.5）上，以 4,000 章、每章 12 页连续翻页，共 48,000 次：

- 修改前：2,278,489 微秒，192,048,000 次章节页表查找。
- 修改后：26,880 微秒，103,998 次查找。
- 定位测试约快 84.8 倍，查找减少 99.9458%。

测试使用已缓存页表，去除磁盘写入和文字排版，以单独测量页定位。数字不代表整机渲染或完整翻页动画速度。回归同时核对原文位置、前后越界、向前回看、跨章跳转和重新排版。

页数估算也存在重复工作。globalPage 原来对每个尚未分页的章节调用 charsPerPage，后者每次遍历所有已缓存页。现在一次 globalPage 调用共用一个估算值，保留原来的取整与精确页数语义。

4,000 章、已缓存 500 章（6,500 页），连续更新总页数 30 次：

- 修改前：3,814,887 微秒；平均每次 127.16 毫秒；扫描缓存 105,000 次。
- 修改后：8,978 微秒；平均每次 0.299 毫秒；扫描缓存 60 次。
- 页数估算约快 424.9 倍。已分页、部分分页和完全分页时的页数检查通过。

该计算由原生阅读器页脚与进度控制实际调用。实测为 Mini 上的 Flutter 测试，不是手机帧率测试。
